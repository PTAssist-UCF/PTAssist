# Frontend

One React web app with a patient side and a therapist side. It talks only to the backend API.

## Stack

React, Vite, TypeScript, Mantine (UI), React Router, Clerk React SDK (sign-in), Orval (API hooks generated from the backend's OpenAPI spec). Hosted on Azure Static Web Apps.

## Layout

```
src/
  api/          Generated by Orval. Do not edit by hand
  components/   Shared UI pieces (for example the result view)
  hooks/        Shared hooks (for example status polling)
  pages/
    patient/    My plan, upload, results, history
    therapist/  Patients, plan builder, patient detail, progress
```

## Run locally

Requires Node 22.13+ (ESLint 10 needs it).

```bash
cd frontend
npm ci
npm run dev
```

The dev server starts at `http://localhost:5173`.

## Sign-in and roles

1. The user signs in with Clerk.
2. The app calls `GET /me` with the Clerk token and gets the role.
3. The router sends patients to `/patient` and therapists to `/therapist`, and blocks the other side's routes.

The frontend never decides access on its own. The backend checks every request; route guards are only for a clean user experience.

## Talking to the API

- Every request carries the Clerk token.
- Use the generated hooks in `src/api/`. When the backend changes, regenerate them (`npm run generate:api`, added in Sprint 1). Never hand-edit generated files.

## Upload and results

1. The patient picks or records a video for an assigned exercise and uploads it.
2. The session starts as `processing`. The page polls the status every few seconds.
3. On `complete`, show reps, form score, and feedback. On `failed`, show the reason and offer a re-upload.

## Config

Environment variables in `frontend/.env` (see `.env.example` in this folder): API URL and Clerk publishable key. Vite only exposes variables that start with `VITE_`.

## Tooling

npm. Lint with ESLint 10 (with `typescript-eslint` and the React hooks plugin's recommended rules), format with Prettier. The React hooks rules also catch common React mistakes, such as setting state directly inside an effect. If one of them gets in the way, ask the team before turning it off in `eslint.config.js`.

- `npm run dev`: start local Vite development server at `http://localhost:5173`
- `npm run build`: typecheck with `tsc` and create production bundle in `dist/`
- `npm run preview`: preview production bundle locally
- `npm run lint`: run ESLint checks across codebase
- `npm run lint:fix`: run ESLint with autofix
- `npm run format`: format code using Prettier
- `npm run format:check`: verify formatting with Prettier

## Pull request CI

The shared workflow in `/.github/workflows/pr-ci.yml` runs two web checks on every pull request, next to the API and AI checks. Both install with `npm ci` on Node 22:

- `Web lint`: ESLint (`npm run lint`) and Prettier (`npm run format:check`).
- `Web build`: `npm run build`, which type-checks the code with TypeScript (`tsc -b`) and then builds the production bundle with Vite.

Run the same three commands before you push. If `format:check` fails, `npm run format` fixes it.

Keep the job names stable: the repository ruleset matches checks by name (see `backend/README.md`, Required checks on main).
